01 — Two ways we'll work

New features vs. small tweaks.
Different process for each.

Not everything needs the same workflow. Bigger pieces get a clean separation. Small fixes stay quick.

New pages or big components

Build it as a standalone HTML file

Open a fresh HTML file. Design the full UI there — all the CSS, layout, colors, everything. Don't worry about the real app structure. I'll take your design and port it into the actual codebase with proper components and logic.

Why this works: You get full creative freedom. No merge conflicts. No risk of breaking existing code. I get a clean reference to implement from.

Small UI tweaks on existing pages

Edit in the codebase, but on agreed files only

We agree every morning on which files you'll touch today. You edit only those files. I stay out of them until you're done. When you push, I pull your changes and continue from there.

Key rule: We never edit the same file on the same day. If you need a file I'm working on, we talk about it first.

02 — The daily routine

A 15-minute morning sync
saves hours of merge headaches.

Morning

15-min sync

We agree: "Today you touch these files, I touch these." Quick chat, nothing formal.

During day

Work in parallel

You do your UI changes on your files. I do functionality on mine. No overlap.

When done

You push, message me

Commit your changes (small commits!), push, and drop me a message. I pull and build on top.

If stuck

Ask before touching a new file

Need to change a file that wasn't in the plan? Quick message first. Takes 10 seconds, saves an hour.

Do

  • Edit only agreed files
  • Commit often (after each meaningful change)
  • Push completed work, not half-done files
  • Message me when you've pushed
  • Ask if you're unsure about a file

Avoid

  • Don't rename or delete components/functions
  • Don't change import lines at the top of files
  • Don't save one giant commit at end of day
  • Don't edit files we didn't agree on
  • Don't restructure folders

If something looks broken after your change — stop and message me. Don't try to fix code you don't understand. That's my job. Your job is making it look great.

03 — Git basics you'll need

Five commands. That's it.
Everything else, I'll handle.

Git tracks every change you make so we can combine our work safely. You only need to know these five things.

Step 1 Pull latest changes before you start working. This grabs any updates I've made. Always do this first thing.
Step 2 Make your UI changes. Work normally in the code. Edit the files we agreed on. Save as you go.
Step 3 Stage your changes. Tell Git which files to save. You can do this after each meaningful piece, not just at the end.
Step 4 Commit with a short message. A one-liner that says what you changed. "Updated sidebar layout" is perfect.
Step 5 Push to the remote. This uploads your work so I can see it. Message me after you push.
Terminal
# 1. Pull latest (always do this first)
git pull

# 2. Make your changes in the editor...

# 3. Stage changed files
git add filename.tsx

# 4. Commit with a message
git commit -m "updated sidebar layout"

# 5. Push to remote
git push

# Repeat steps 3-5 for each chunk of work
# Small commits > one big commit

Commit often, push when done. Think of commits like "save points." Each one should be a complete, working change — not a half-finished file. 3–5 commits per day is great. 1 giant commit is what we're moving away from.
